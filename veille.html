Utilisation d'Ansible avec Linux et Windows

Sujet

Ma veille porte sur l'utilisation d'Ansible pour automatiser l'administration de machines Linux et Windows dans un parc informatique.

Problématique : comment administrer plusieurs systèmes avec un seul outil d'automatisation ?

Qu'est-ce qu'Ansible ?

Ansible est un outil open source d'automatisation informatique. Il permet d'installer des logiciels, configurer des serveurs, deployer des applications et executer des taches d'administration sur plusieurs machines.

Il fonctionne avec des fichiers appeles playbooks, ecrits en YAML. Ces playbooks decrivent les actions a effectuer. Ansible applique ensuite ces actions sur les machines indiquees dans un inventaire.

Fonctionnement general

  • Une machine de controle lance les commandes Ansible.
  • Un inventaire liste les serveurs Linux et Windows a administrer.
  • Les playbooks decrivent les actions a realiser.
  • Les modules Ansible executent les actions : installation, copie de fichiers, services, utilisateurs, mises a jour.
  • Ansible est agentless : il n'est pas necessaire d'installer un agent permanent sur chaque machine.

Utilisation avec Linux

Sur Linux, Ansible utilise principalement SSH. C'est simple car SSH est deja present sur la plupart des serveurs Linux.

  • Connexion avec une cle SSH ou un mot de passe.
  • Utilisation de become pour executer certaines taches avec les droits administrateur.
  • Modules courants : apt, dnf, service, copy, template, user.
  • Cas d'usage : installer Apache, configurer un firewall, creer un utilisateur, deployer un fichier de configuration.

Utilisation avec Windows

Sur Windows, Ansible utilise surtout WinRM, un protocole de gestion a distance integre a Windows. Ansible peut aussi utiliser OpenSSH avec Windows, mais il faut respecter les versions supportees.

  • Connexion WinRM en HTTP ou HTTPS, avec une configuration prealable de la machine Windows.
  • Modules Windows : win_updates, win_service, win_user, win_copy, win_package.
  • Cas d'usage : installer un logiciel, gerer un service Windows, creer un utilisateur, appliquer des mises a jour.
  • Bonne pratique : privilegier WinRM en HTTPS ou une authentification adaptee au domaine.

Exemple d'inventaire

[linux]
srv-web ansible_host=192.168.1.10 ansible_user=admin

[windows]
pc-support ansible_host=192.168.1.20

[windows:vars]
ansible_connection=winrm
ansible_user=Administrateur
ansible_password=mot_de_passe_a_chiffrer
ansible_winrm_transport=ntlm

Exemple de playbook

---
- name: Installer Apache sur Linux
  hosts: linux
  become: true
  tasks:
    - name: Installer apache2
      apt:
        name: apache2
        state: present

- name: Verifier un service Windows
  hosts: windows
  tasks:
    - name: Demarrer le service Spooler
      win_service:
        name: Spooler
        state: started

Interet pour une entreprise

  • Gagner du temps sur les taches repetitives.
  • Limiter les erreurs humaines pendant les installations et configurations.
  • Gerer Linux et Windows dans un meme outil.
  • Documenter les actions grace aux playbooks.
  • Rejouer une configuration identique sur plusieurs machines.

Points de vigilance

  • Ne jamais stocker les mots de passe en clair : utiliser Ansible Vault.
  • Tester les playbooks sur un environnement de test avant la production.
  • Verifier les droits administrateur sur Linux et Windows.
  • Bien separer les groupes Linux et Windows dans l'inventaire.
  • Sur Windows, verifier la configuration WinRM, le firewall et le mode d'authentification.

Actualite de la veille

Au 7 juillet 2026, la communaute Ansible publie regulierement des versions. Ansible 14.1.0 a ete annonce en juin 2026 et depend d'ansible-core 2.21.1. Cela montre que le projet reste actif et maintenu.

La documentation officielle met aussi en avant deux possibilites pour Windows : WinRM, qui reste la solution courante, et OpenSSH lorsque l'environnement Windows respecte les conditions de support.

Conclusion

Ansible est interessant pour administrer un parc mixte Linux et Windows. Linux est gere facilement avec SSH, tandis que Windows demande une configuration WinRM ou SSH plus precise. Pour une entreprise, Ansible permet de standardiser les configurations, gagner du temps et fiabiliser les deploiements.
